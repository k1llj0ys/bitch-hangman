How this works (and what it does not protect)
  1. Play a game — type a word yourself, or paste an encrypted word someone sent you. Seven wrong guesses and the character gets a beer.
  2. Generate a word — type the secret, press Encrypt, and copy the payload. Send only the payload; the plaintext never leaves your browser.
  3. The app ships with one built-in key pair, so both jobs work with no setup. Swap it in Key settings if you want your own.
  • Nothing is loaded from a server during play: no CDN, no web fonts, no remote images, no analytics, no backend.
  • Heads-up about the built-in key: its private half is published with this page, so anyone who can open the app can decrypt payloads made with it. It is a convenience default, not a secret. Generate your own pair in Key settings for anything that matters.
  • Your own key (once you generate or restore one) is remembered in this browser’s localStorage, scoped to this origin. It never leaves this PC through the app.
  • Normalisation: NFC is applied, accents fold to their base letter (É is revealed by guessing E), and non-Latin letters with no A-Z equivalent are shown automatically so they never trap the game.

Running from file://? Browsers disable Web Crypto there. Use start-game.bat, which serves the app on http://127.0.0.1.
